Medical model inference on Apple Silicon: corrections and tested evidence

A scoped fork of MLX-VLM corrects reproducible errors in the Gemma3/MedGemma path. The evidence supports inference correctness on the tested cases. Clinical accuracy and a performance advantage remain unmeasured.

Local development candidate. The recorded checks describe a dated review. No checkpoint was retrained or published.

Corrections and their consequences

Observed problemImplemented behavior
Gemma generation dropped the image attention mask; direct forward allowed future text.Causal text attention and bidirectional attention within each image block persist through decoding, padding and rotating sliding caches.
MedGemma's actual width of 2560 conflicted with a default width of 2048.Feature scaling derives from the actual embedding width and cancels the exact language embedding scaler.
Gemma scaled caller-owned embeddings in place.Language inference preserves the supplied embedding array.

Numerical evidence

The reference is Transformers 5.19.0 with Torch 2.14.1 on CPU. The candidate uses MLX 0.32.3 on an Apple M1 Max with 64 GiB memory, Metal, FP32 and MLX_ENABLE_TF32=0. Tiny models share the same weights. The fixed tolerance is atol=2e-5, rtol=2e-5; masks and placement order require exact agreement.

  • Complete Gemma pixels-to-logits path: maximum absolute error 1.2666e-7. The fixture uses nonzero projector weights and requires changed pixels to change logits.
  • Gemma projected image features: maximum absolute error 4.4704e-8. Attention masks agree exactly.
  • Additional cases cover multiple images, cache rotation, requested prefill chunk sizes, missing/surplus features, nonfinite features and property-based placement/mask checks.

Inspect the numeric contract and regression tests. These FP32 checks do not establish numerical parity for full quantized medical checkpoints.

Real checkpoint integration

The pinned 4-bit checkpoints load with strict weight matching and run through the public image generation entrypoint. Their exact revisions are recorded in the checkpoint manifest. The smoke input is a public CC0 normal PA chest radiograph, downloaded per run, with the prompt “Describe this chest X-ray.” Observed on 2026-10-30 with greedy decoding and up to 128 new tokens:

Scope and implementation decisions

Inference-only package. SFT/ORPO trainers, fine-tuning datasets and CLI, optimizer helpers, and custom rotary gradient hooks are removed. Pretrained LoRA/DoRA adapters load through one inference action that checks their targets and tensors before changing the model. Retaining trainer utilities in the inference loader was rejected because it imported training machinery into ordinary model loading. The general evaluation extra was removed in the version 0.2 medical scope cutover.

The qualified paths are direct model calls and single-request autoregressive generation. The suite includes synthetic padded direct batches. Continuous batching, automatic prefix caching, speculative multimodal decoding, video timestamps, long-context memory use and additional inherited architectures are outside this qualification.

Runtime scope. The source retains MedGemma, shared inference infrastructure and text HTTP protocols. The broader catalog and media-generation entry points were removed. The measurements above describe the dated review, not a new qualification of every current service path.

Whole image prefill. Gemma prompts containing image tokens are prefilled as a whole. Arbitrary chunks can divide a bidirectional image block before all its keys exist. Such partial blocks are rejected explicitly; text-only chunked prefill remains enabled. Image-aligned scheduling is deferred. Full prompt masks require quadratic memory in prompt length, so long-context throughput and memory need separate measurement.

Maintained fork. A complete rewrite was rejected because the reproduced failures are localized and upstream already provides weight loading, quantization, tokenization, vision encoders and generation infrastructure. Retaining that infrastructure keeps attribution intact and makes the corrected behavior directly comparable. A universal claim of superiority is not supported.

Use an isolated environment: this distribution is named med-vlm-mlx but intentionally retains the mlx_vlm import namespace. The MLX backend is selected explicitly and the medical suite requires Metal. Smoke checks download model weights when absent. They require a nonempty generation; output quality must be interpreted separately.
